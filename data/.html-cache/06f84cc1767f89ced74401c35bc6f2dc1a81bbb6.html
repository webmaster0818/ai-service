開発背景

事業環境の変化のスピードは年々増しており、企業が状況を的確に捉え、意思決定を更新し続けるためには、AI活用が必要不可欠となっています。また、AIの精度向上には社内用語の意味や定義など、AIがデータを正しく解釈するためのコンテキストの整備が欠かせない要素です。変化のスピードに追随し続けるには、このコンテキストの整備自体を自律化していく必要があります。

コンテキストの整備を自律的に進めるうえで課題となるのが、ビジネス部門とシステム部門の分断です。ある用語が業務でどのような意味を持つかを把握しているのはビジネス部門であり、それがデータ上のどの値に対応するかを確認できるのはシステム部門です。必要な知識が部門をまたいで分かれているため、ひとつの用語を登録するにも双方のやり取りが欠かせません。また、システム部門は、ビジネス部門が実際にどのようなデータを求めているかを把握する手段が限られているため、数多くある候補の中から優先して整備すべきコンテキストを判断することも容易ではありません。

COMETAは、テーブルやカラムの説明、社内用語とその定義をまとめた「用語集」など、このコンテキストを管理し、自然言語での対話を通じてデータの探索や分析を行える「AIチャット」機能を備えています。今回追加する「コンテキスト自律整備」機能は、ビジネス部門とシステム部門の分断をAIで解消する機能です。ビジネス部門がAIチャットに入力した質問には、その部門が業務でどの用語を使い、何を明らかにしようとしているかという情報が記録されています。本機能は、従来は部門間のやり取りを重ねなければ把握できなかったこのデータをAIが分析し、次に整備すべきコンテキストを優先度とともに示すとともに、登録に用いる定義の文案まで作成します。これにより部門間のやり取りの負担を抑え、事業環境の変化に応じてコンテキストが自律的かつ継続的に整備される状態を実現します。

「コンテキスト自律整備」の主な機能

AIチャットの利用状況を可視化

管理者権限を持つユーザーが対象期間と対象ユーザーを指定して分析を実行すると、AIがCOMETAのAIチャットの利用状況を分析し、AIチャットの利用件数、利用ユーザー数、該当のチャット履歴の詳細等を提示します。AIチャットがどういった業務の中で活用されているかを把握することが可能です。

整備すべき用語の優先度付き提案

用語集に登録されていない用語について、新規に登録すべき用語と定義を見直すべき用語を優先度順に整理し、それぞれに登録用の文案を付与します。既存の用語集に該当しない領域がある場合は、新たな用語集の作成もあわせて提案します。

今後の展望

AIを経営に活かせるかどうかは、社内の暗黙知をAIが理解できているかに大きく左右されます。ここでいう暗黙知とは、その企業でしか通じない用語の定義、特定の担当者しか把握していない社内ナレッジ、事業とともに移り変わる指標の意味を指します。これらが欠けたままでは、AIは問いの意図を取り違え、答えが返ってきても現場はそれを信用することができません。primeNumberは、AIが適切に機能するための前提となるコンテキストを充実させ、人の関与を最小限に抑えながら、誰もが自社のデータを正しく活用できる世界を目指しています。これは、primeNumberが提唱する、データとAIを駆使した次世代の経営手法「Generative Data Management（GDM）」が描く姿そのものです。

この実現に向けて、「コンテキスト自律整備」機能を段階的に拡張していきます。まずは用語集を対象に提供を開始し、現場で活用されているにも関わらず整備が追いついていないコンテキストを継続的に育てていく状態を実現します。今後は対象をテーブルやカラムのメタデータへと広げ、説明不足が生じている箇所や見直を必要としている箇所についても、AIが過不足を検知してレコメンドできるようにしていきます。最終的には、提案にとどまらず、コンテキストの整備そのものをAIが実行できる状態を目指し、GDMの実現につなげます。

]]> クラウドETL「TROCCO」、AI活用でニーズが高まる非構造化データの転送を可能にする新機能を提供開始 https://primenumber.com/news/47133/ Tue, 29 Sep 2026 02:00:00 +0000 https://d2mnveqpklnoao.cloudfront.net/?p=47133 データとAIを企業の成長エンジンへと進化させるデータテクノロジーカンパニーの株式会社primeNumber（本社：東京都品川区、代表取締役CEO：田邊 雄樹）は、クラウドETL「TROCCO」において、ファイルの内容を変換せずに非構造化データをそのまま転送する「ファイル転送」機能を、2026年10月15日より提供開始します。本機能により、PDF・画像・帳票などの非構造化データを、データ基盤へ集約・分析活用できるようになります。基幹システムが出力するファイルの連携から、データウェアハウス（DWH）のAI機能を用いた分析まで、TROCCOで扱える業務領域が広がります。新機能により、これまで分散していた非構造化データがデータ基盤へ集約され、AI-Readyな基盤整備が進み、primeNumberが提唱するデータとAIを駆使した次世代の経営手法「Generative Data Management（GDM）」を推進します。 

機能強化の背景

企業におけるAI活用が加速する中、AIが参照するデータの質と量が、分析精度や意思決定の成果を大きく左右する時代を迎えています。多くの企業には、テーブル形式では表せない基幹システムが出力する独自形式ファイルや、業務のなかで作成される手順書や契約書などのPDF、画像といった業務ファイルなど、非構造化データが蓄積されています。これらをデータ基盤へ転送するには、あらかじめ加工してクラウドストレージにアップロードするなど、個別の開発が必要でした。

TROCCOはこれまで、データの「収集」と「送信」の両面で機能を継続的に強化してきました。収集の領域では、対応コネクタの大幅な拡張に加え、ユーザー自身がコネクタを開発できる「カスタムコネクタ」、オンプレミス環境や閉域ネットワーク内のデータを扱える「Self-Hosted Runner」などを提供しています。送信の領域では、DWHに蓄積したデータを業務システムへ還元する「リバースETL」の対応先を広げてきました。いずれの機能も、転送するデータをテーブル形式で扱うことを前提としていたため、非構造化データは対象外としてきました。

昨今、DWHに実装されたAI機能によって非構造化データを直接扱えるようになり、画像やPDFを読み取り内容を判定し、データを構造化する処理が現実的になってきました。従来はPythonなどでプログラムを書かなければ実現できなかった処理が、自然言語による指示で実行できるようになっています。

このような背景からこの度TROCCOでは、転送できるデータの種類を非構造化データまで広げます。収集と送信の両面で対応範囲を広げてきた従来の機能強化に加え、扱えるデータの種類を拡張することで、企業に蓄積された様々なデータをより広くAI活用につなげられるようになります。

「ファイル転送」機能概要

この新機能はファイルを変換せず、そのままの形でデータを転送する機能です。拡張子や形式を問わず、PDF・画像・独自形式ファイルなどを転送でき、転送先には元のファイルと同一の状態で格納されます。元のファイルが保たれるため、契約書や帳票のように原本のまま扱う必要がある文書も対応可能です。

また、本機能は、構造化データを扱う既存のデータ転送設定とは別に「ファイル転送設定」として管理します。ワークフローに組み込むことで、定期実行、後続のデータ加工、通知と組み合わせた運用が実現できます。転送元と転送先の差分を判定し、変更のあったファイルのみを転送するほか、転送の履歴を実行ごとに記録します。

2026年10月15日の提供開始時点では、転送元としてSFTP（SSH File Transfer Protocol）で接続するファイルサーバーを、転送先としてGoogle Cloud Storageに対応します。

なお、本機能は、Advancedプラン以上の契約でご利用いただけます。閉域環境にあるファイルを転送する場合は、Self-Hosted Runner（Professionalプラン）が必要です。

想定されるユースケース

1. 基幹システムのファイル連携・統合管理の実現

従来は、あらかじめ加工してクラウドストレージにアップロードするなどの個別開発が必要でしたが、基幹システムやファイルサーバーが出力する帳票・独自形式ファイルを、そのままデータ基盤へ連携できます。

ファイルを転送するだけでなく、その後のDWHへの取り込み、データ加工、エラー時の通知までをTROCCOのワークフローで一元管理できます。オンプレミス領域のスクラッチスクリプトと、クラウド領域のデータ基盤とで分かれていた運用を、ひとつの基盤に統合することができます。なお、閉域環境にあるファイルを転送する場合は、Self-Hosted Runnerが必要です。

2. DWHのAI機能による非構造化データの分析

DWHのAI機能で扱う画像やPDFを、TROCCOで収集し一元管理できます。たとえば店舗に設置したカメラの画像がサーバーに蓄積されている場合、これらをデータ基盤へ集約し、AI機能で画像の内容を判定しデータを構造化することで、来店者数の推移を数値として分析できるようになります。また、商品の写真画像や、契約書、請求書といったPDFからの情報抽出なども可能となり、分析対象として扱えるようになります。

この様に、分析対象となるファイルの収集をTROCCOに任せることで、AI機能を用いた分析の準備工程を自動化でき、豊富なデータソースを分析に活用できます。

3. 分散した社内文書をAI分析で活用可能に

社内で作成された手順書やマニュアル、仕様書などは、部門ごとに異なるクラウドストレージに蓄積されていることが少なくありません。こうした文書は、生成AIに質問しても回答の根拠として参照されず、結局は詳しい担当者に依存するという状態に陥りがちです。

今後、転送元としてBoxやGoogle Driveなどのストレージサービスへ対応を広げることで、部門ごとに分散したこれらの文書を、TROCCOでひとつの場所へ集約できるようになります。ファイルの転送に続いて、AI側の取り込み処理を呼び出すところまでをワークフローで自動化できるため、文書が追加・更新されるたびに人手で登録し直す必要がありません。変更のあったファイルのみを転送する仕組のため、更新分の反映も自動的に実行されます。これにより、社内に蓄積された知識を、生成AIによる検索や問い合わせ対応チャットボット構築（RAG）などに活かせるようになります。

今後の展望

AI活用の成果は、モデルの性能そのものよりもAIが参照できるデータの質や範囲で決まります。 しかし多くの企業では、業務ファイルなどの非構造化データが部門ごとのストレージなどに分かれて置かれており、その大半はAIから参照されないまま眠っています。「ファイル転送」機能は、こうした状態を変える最初の一歩です。

業務ファイルが蓄積されるのはデータ基盤の中だけとは限らず、日々の業務で使うファイルストレージに置かれたままになっていることもしばしば発生します。転送元として、BoxやGoogle Driveのように手順書や契約書が蓄積されやすいサービスを、転送先としては、Amazon S3などのクラウドストレージを順次追加し機能を拡張していきます。業務ファイルをデータ基盤へ届け、構造化データと非構造化データを組み合わせたAI活用の機会を提供していきます。

また、AIの回答は、根拠となった文書が最新のものか、参照する人に開示してよい情報かによって信頼性が左右されます。転送元での変更や削除への追随に加え、更新日時やアクセス権限といったメタデータをファイルとともに引き渡す仕組みを整え、AIが扱うデータの鮮度と取り扱い範囲を管理できる機能を強化していきます。

さらに、取引先から受領した文書のように社外から届くファイルには、従来のデータ転送とは異なるリスクが伴います。AI時代のデータ活用を安心・安全に進めるための機能拡張にも投資していきます。
