2026年11月18日21時の回以降に確認したニュースのうち、公式発表を確認できた4件をまとめました（AI 2件、システム・開発基盤 1件、セキュリティ 1件）。
GitHub CopilotでのGemini 4 Neonの一般提供、CloudflareによるClairic・Clairic-flashのオープンウェイト公開、GitHub Teamでのセキュリティリスク評価の自動実行、CISAによる悪用済み脆弱性カタログ（KEV）への4件追加を取り上げます。

当サイトでは、各社・各機関の公式発表を開いて内容を照合したうえで掲載しています。数字や日付は各項目末尾の出典番号から確認できます。時刻は日本時間で記載しています。

## AI

### 1. GitHub Copilot、Gemini 4 Neonを一般提供　Pro+・Max・Business・Enterpriseが対象

GitHubは2026年11月18日（日本時間11月19日6時49分ごろ）、GoogleのGemini 4 NeonをGitHub Copilotで一般提供したと発表しました。エージェント型のコーディング、複数段階のツール利用、ナレッジワーク向けのモデルで、料金は従量課金のもとでモデル提供元の定価で請求されます [1]。
対象はCopilot Pro+、Max、Business、Enterpriseの利用者で、Visual Studio Code、Visual Studio、Copilot CLI、Copilot coding agent、github.com、GitHub Mobile、JetBrains IDE、Xcode、Eclipseなどのモデル選択画面から選べます。提供は段階的に進めるとしています [1]。

<figure><img src="/images/news/news-20261119-08/1.webp" alt="出典[1]のページ（github.blog）のキャプチャ" width="1280" height="800" loading="lazy" /><figcaption>出典 [1] GitHub Changelog「Gemini 4 Neon in GitHub Copilot」2026年11月18日（github.blog・2026年11月19日 08:04 当サイト取得）</figcaption></figure>

**企業・担当者が確認すること：** BusinessとEnterpriseでは、管理者が既定の自動有効化を止めていない限り、新しいモデルは自動で有効になります [1]。当サイトでは、従量課金のモデルが社内で使われ始める前に、Copilot設定のモデルポリシーと利用料金の上限を確認することをおすすめします。

### 2. Cloudflare、文書抽出モデル「Clairic」「Clairic-flash」をオープンウェイトで公開

Cloudflareは2026年11月18日（日本時間11月19日7時ごろ）、テキスト・画像・PDFから情報を抽出するモデル「Clairic」（270億パラメーター）の更新版を公開し、軽量版の「Clairic-flash」（90億パラメーター）をWorkers AIに追加したと発表しました。更新版はプレビュー版と同じエンドポイント（@cf/cloudflare/clairic）で順次置き換わります。2つのモデルの重みはHugging Faceで公開されています [2]。
料金は入力トークンのみの課金で、Clairic-flashは100万入力トークンあたり0.10ドル、Clairicはキャンペーン終了後に0.24ドルです。2026年12月1日までは両モデルとも0.10ドルとしています [2]。

<figure><img src="/images/news/news-20261119-08/2.webp" alt="出典[2]のページ（blog.cloudflare.com）のキャプチャ" width="1280" height="800" loading="lazy" /><figcaption>出典 [2] Cloudflare Blog「An updated Clairic and Clairic-flash are now open-wei…（blog.cloudflare.com・2026年11月19日 08:04 当サイト取得）</figcaption></figure>

**企業・担当者が確認すること：** プレビュー版のエンドポイントを使っているアプリケーションは、自動で更新版に切り替わります [2]。当サイトでは、抽出結果を業務に使っている場合は切り替え後の出力を確認することをおすすめします。また、請求書や申込書などの読み取りに使う場合は、Workers AIで利用するか、公開された重みを自社環境で動かすかを、扱うデータの社外持ち出し可否と合わせて検討することをおすすめします。ライセンス条件は公開先で確認してください [2]。

## システム・開発基盤

### 3. GitHub Team、セキュリティリスク評価が自動で実行されるように　認証情報の露出と脆弱性を把握

GitHubは2026年11月18日、GitHub Teamプランの組織で、セキュリティリスク評価が自動で実行されるようになったと発表しました。評価は無料で、組織の管理者とセキュリティマネージャーが、露出している認証情報（シークレット）やコードの脆弱性に関する結果を確認できます [3]。

**企業・担当者が確認すること：** GitHub Teamを利用している組織の管理者は、評価結果を確認し、検出された認証情報の無効化と再発行を優先してください。当サイトでは、結果を確認する担当者と対応期限を社内であらかじめ決めておくことをおすすめします。

## セキュリティ

### 4. CISA、悪用が確認された脆弱性4件をKEVに追加　LiteLLMやSynology DSMなど

米国CISA（サイバーセキュリティ・インフラストラクチャセキュリティ庁）は2026年11月18日、実際の悪用の証拠に基づき、4件の脆弱性を「既知の悪用された脆弱性（KEV）カタログ」に追加しました。対象はSynology DiskStation Manager（CVE-2024-10441）、BerriAI LiteLLM（CVE-2026-40217）、Apache Axis（CVE-2026-90436）、Vanderbilt University REDCap（CVE-2026-90817）です [4]。
このうちLiteLLMの脆弱性は、2026年4月8日までのLiteLLMで、/guardrails/test_custom_code へのバイトコード書き換えにより遠隔から任意のコードを実行されるおそれがあるもので、CVSS 3.1の基本値は8.8です。NVDでは米国連邦政府機関の対応期限を2026年12月2日としています [5]。

<figure><img src="/images/news/news-20261119-08/4.webp" alt="出典[4]のページ（www.cisa.gov）のキャプチャ" width="1280" height="800" loading="lazy" /><figcaption>出典 [4] CISA「CISA Adds Four Known Exploited Vulnerabilities to Catalog」2026年1…（www.cisa.gov・2026年11月19日 08:04 当サイト取得）</figcaption></figure>

**企業・担当者が確認すること：** LLMの中継（プロキシ）サーバーとしてLiteLLMを使っている場合は、バージョンを確認して最新版に更新し、管理用の画面やAPIをインターネットに公開していないかを確認してください [5]。当サイトでは、Synology製NASやREDCapを利用している組織も、ベンダーの案内に沿って更新状況を確認することをおすすめします。
