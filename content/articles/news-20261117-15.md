2026年11月16日21時から11月17日15時までに確認したニュースのうち、公式発表を確認できた5件をまとめました（システム・開発基盤分野2件、セキュリティ分野3件）。
GitHub Copilotまわりの提供終了2件と、AIを使った攻撃の動向レポート、国内で使われている業務ソフト・ルータの脆弱性を取り上げます。

当サイトでは、各社・各機関の公式発表を開いて内容を照合したうえで掲載しています。数字や日付は各項目末尾の出典番号から確認できます。時刻は日本時間で記載しています。

## システム・開発基盤

### 1. GitHub Copilot、Claude Opus 4.8・Claude Opus 5・GPT-5.6 Terraの提供を大半の機能で11月16日に終了

GitHubは2026年11月16日、Claude Opus 4.8、Claude Opus 5、GPT-5.6 Terraの3つのモデルについて、Copilot Chat、インライン編集、askモード・agentモード、コード補完を含むGitHub Copilotの大半の機能で、同日付で提供を終了したと公表しました。終了は10月15日に予告されていたものです。ただし、Claude Opus 4.8は年額プランの個人契約者には引き続き提供され、Claude Opus 5はモデル選択の一覧から外れたものの、既存の権限による応答拒否時の代替（runtime refusal fallback）では引き続き使われるとしています [1]。
代わりのモデルとして、Claude Opus 4.8とClaude Opus 5にはClaude Opus 5.5を、GPT-5.6 TerraにはGPT-6.1 SolまたはGPT-6 Lunaを挙げています。Copilot Enterprise・Businessで既定のモデル有効化設定のままにしている組織では、代わりのモデルが自動で有効になります。管理者が全体の既定を無効にしている場合や、個別のモデルを無効にしている場合は、Copilotの設定のモデルポリシーから代わりのモデルを有効にする必要があるとしています [1]。

**企業・担当者が確認すること：** Copilotの管理者は、代わりのモデルが組織で有効になっているかを確認してください。終了した3モデルを名指しで使っている業務フローや連携があれば、利用できるモデルに切り替えてください [1]。

### 2. VS Codeの「Local harness」、2027年2月に削除　Copilotのエージェントセッションは「Copilot」harnessへ移行

GitHubは2026年11月16日、VS CodeでGitHub Copilotのエージェントセッションを動かす旧来の仕組み「Local harness」を、VS Code 1.146で非推奨にし、2027年2月に削除すると公表しました。移行先は、VS Codeに組み込まれ、バージョン1.143から新しいセッションの既定になっている「Microsoft Copilot harness」です [2]。
切り替えは、新しいセッションを始めて「Session Target」で「Copilot」を選ぶ方法です。harnessを切り替えても、すべてのカスタマイズが自動で変換されるわけではないため、事前に見直すよう求めています。管理者が設定している例外設定 `vscode.temporaryDefaultToLocalHarness` も、Local harnessとともに削除されるとしています [2]。

<figure><img src="/images/news/news-20261117-15/2.webp" alt="出典[2]のページ（github.blog）のキャプチャ" width="1280" height="800" loading="lazy" /><figcaption>出典 [2] GitHub Changelog「VS Code retires the Local harness in February 2027」2…（github.blog・2026年11月17日 15:07 当サイト取得）</figcaption></figure>

**企業・担当者が確認すること：** VS Codeで今もLocal harnessを使っている開発チームは、2027年2月までにCopilot harnessへ切り替え、カスタマイズが引き継がれているかを確認してください。`vscode.temporaryDefaultToLocalHarness` を配布している管理者は、設定の見直しが必要です [2]。

## セキュリティ

### 3. Google脅威インテリジェンスチーム、攻撃者がAIエージェントで脆弱性の発見から悪用まで自動化していると報告

Google Threat Intelligence Group（GTIG）は2026年11月17日付で、攻撃者による生成AIの悪用動向をまとめた四半期レポートを公表しました。この四半期に、攻撃者がLLMを使ったフレームワークで、脆弱性の発見から悪用までを人の手を介さずに自動化している例を初めて確認したとしています。修正の公開前後のコードを比べて脆弱性を特定し、攻撃コードを作って自動で実行する仕組みだと説明しています [3][4]。
このほか、ARTEX、CAIRN、CyberStrikeAI、PentAGIといったオープンソースの侵入テスト用マルチエージェントフレームワークが実際の侵入に悪用されていること、企業環境から盗んだLLMの認証情報やクラウド資源を地下の代理サービスで転売する「LLMJacking」が続いていることを挙げています。北朝鮮との関連が疑われるグループが、侵入先の社内リポジトリでClaude Codeの設定ファイル（`.claude/settings.json`）を書き換え、起動時にバックドアを取得させていた事例も報告しています [3]。

**企業・担当者が確認すること：** 公開サーバーの修正プログラムは公開後すぐ適用する前提で運用を見直してください。社内のLLMのAPIキーやクラウドの認証情報の利用状況を監視し、リポジトリ内のAIコーディングツールの設定ファイルが意図せず変更されていないかを確認してください [3]。

### 4. プリザンターに4件の脆弱性、他ユーザーのAPIキー取得など　修正版1.5.10.0を公開

インプリムは2026年11月17日、業務アプリ作成ツール「プリザンター」に4件の脆弱性があると公表し、修正版1.5.10.0を同日リリースしました。JVNも同日、CVE-2026-117634、CVE-2026-121811、CVE-2026-125276、CVE-2026-125411として公表しています。Community Edition、Enterprise Editionの両方が対象です [5][6]。
このうちCVE-2026-125276（バージョン1.2.24.0から1.5.9.1が対象）は、ログインしてAPIを使えるユーザーが、管理者を含む同じテナントの他ユーザーのAPIキー等を取得でき、そのユーザーになりすまして操作できるものです。CVE-2026-117634は、情報公開機能で公開したサイトがリンク項目を持つ場合に、ログインしていない第三者が非公開のレコードのタイトルや、ユーザーの氏名・グループ名・組織名を取得できるものです。API機能を無効にしている場合は、APIに関する2件の影響を受けません [5][6]。

**企業・担当者が確認すること：** プリザンターを使っている企業は、バージョンを確認して1.5.10.0へ更新してください。すぐに更新できない場合は、APIや情報公開機能の利用状況を確認し、開発元が示している回避策を検討してください [5][6]。

### 5. エレコム製無線LANルータ3機種にOSコマンドインジェクションの脆弱性（CVE-2026-101113）

JVNは2026年11月17日、エレコム製の無線LANルータWRC-BE36QS-B、WRC-BE36QSD-B、WRC-W701-Bのそれぞれv2.1.3およびそれ以前のバージョンに、OSコマンドインジェクションの脆弱性（CVE-2026-101113）があると公表しました。管理画面にアクセスできる攻撃者によって、任意のOSコマンドを実行されるおそれがあります [7]。
CVSS v4.0の基本値は8.6、CVSS v3.1の基本値は7.2です。開発者が提供する情報をもとに、ファームウェアを最新版へ更新するよう求めています [7]。

<figure><img src="/images/news/news-20261117-15/5.webp" alt="出典[7]のページ（jvn.jp）のキャプチャ" width="1280" height="800" loading="lazy" /><figcaption>出典 [7] JVN「JVNVU#92504317 エレコム製無線LANルータにおけるOSコマンドインジェクションの脆弱性」2026年11月17日（jvn.jp・2026年11月17日 15:07 当サイト取得）</figcaption></figure>

**企業・担当者が確認すること：** 事務所や店舗で対象機種を使っている場合は、ファームウェアのバージョンを確認して最新版へ更新し、管理画面のパスワードが初期値のままになっていないかを確認してください [7]。
