## AI・システム

### 1. GitHub Enterprise、ライセンス利用者全員にCopilotを含める形態を開始

GitHubは2026年10月28日、GitHubまたはMicrosoftのアカウントチームと契約している企業向けに、GitHub Enterpriseのライセンスを持つすべての利用者がCopilotを使える形態の提供を始めたと発表しました。対象はGitHub Enterprise Cloudで、既存・新規の企業アカウントとも営業経由で移行できます。セルフサービスで契約している企業への提供は段階的に進め、日程は今後数週間のうちに案内するとしています [1]。
この形態ではCopilot Enterpriseと同じ機能・モデルを使えますが、1席あたりの月間AIクレジットはなく、最初のリクエストから企業の予算に対して従量で計測されます。予算が無くなってもコード補完と次の編集候補（next edit suggestions）は使え、Copilot Chat、Copilotのコードレビュー、クラウド上のCopilotは予算が必要です。GitHub Enterpriseのライセンスを持たない利用者向けには、1人あたり月10ドルの「Copilot Standalone」が用意されます。Copilot BusinessとCopilot Enterpriseは引き続き購入できます [1]。

### 2. GitHub Agentic Workflows が一般提供に

GitHubは2026年10月28日、GitHub Actionsの中でコーディングエージェントを動かし、issueのトリアージ、CIの失敗の分析、ドキュメントの更新、テストの作成などを自動化する「GitHub Agentic Workflows」を一般提供（GA）にしたと発表しました。自然言語で書いたMarkdownファイルを標準のActionsのYAMLにコンパイルする仕組みで、github.com上のGitHub Free、Team、Enterpriseで使えます [2]。
既定のGitHub Copilot CLIエンジンで動かすにはCopilotのライセンスが必要です。権限は既定で読み取り専用で、サンドボックス内での実行や、提案された変更を適用前にスキャンする脅威検出ジョブなどの安全対策が組み込まれているとしています。AIクレジットの支出を見積もる `gh aw forecast` は実験的機能ではなくなりました [2]。

## セキュリティ

### 4. CISA、VMware ESXとLinuxカーネルの脆弱性を悪用確認済みカタログに追加

米国のサイバーセキュリティ・インフラストラクチャセキュリティ庁（CISA）は2026年10月28日、実際に悪用されている証拠があるとして、2件の脆弱性を既知の悪用された脆弱性（KEV）カタログに追加しました [4]。
1件目はBroadcom VMware ESXのログ記録が不十分な脆弱性（CVE-2026-41709）で、管理者権限を持つ攻撃者が一部の操作をログに残さずに実行できるおそれがあります [5]。Broadcomは2026年7月29日に公開したアドバイザリVMSA-2026-0006でこの脆弱性をCVSSv3 基本値2.7（Low）と評価し、ESX 8.0向けのESXi80U3jなどの修正版を示しています。回避策は無いとしています [6]。
2件目はLinuxカーネルの変数の初期化漏れの脆弱性（CVE-2026-46300）で、ソケットバッファの結合時に共有フラグメントの印が保持されず、ページキャッシュ上のデータが意図せず書き換えられるおそれがあります。CISAは、PHPの脆弱性CVE-2026-109618・CVE-2026-109619と組み合わせることで、PHPのWebシェルを設置し、root権限でコマンドを実行できるとしています。米国連邦政府機関向けの対応期限は、VMware ESXが11月11日、Linuxカーネルが10月31日です [5]。

**企業・担当者が確認すること：** VMware ESXはBroadcomのアドバイザリに示された修正版が適用済みかを確認してください [6]。Linuxサーバーはディストリビューションのカーネル更新を確認し、PHPを動かしているサーバーではPHPの更新とあわせて優先して対応してください（当サイトの見解）。

### 5. Apache Struts 2のRESTプラグインで、パラメータの認可チェックが一部に適用されない問題

JVNは2026年10月29日、Apache Struts 2のRESTプラグインで、Jacksonの `@JsonAnySetter` が指定されたフィールドやメソッドに `@StrutsParameter` による認可チェックが行われない問題を公表しました。対象はバージョン7.2.1から7.3.0です [7]。
この問題は、`struts.parameters.requireAnnotations=true` で `@StrutsParameter` を有効にし、RESTリクエストのボディからバインドされるアクションまたはモデルクラスで `@JsonAnySetter` を宣言している場合にのみ発生し、データの改ざんにつながる可能性があります。対策は7.4.0以降への更新で、そのうえで `struts.rest.anySetter.requireAnnotations=true` を設定し、any-setterとして使う各メソッドに `@StrutsParameter(allowDynamicKeys = true)` を付けるよう案内しています [7][8]。

<figure><img src="/images/news/news-20261029-14/5.webp" alt="出典[7]のページ（jvn.jp）のキャプチャ" width="1280" height="800" loading="lazy" /><figcaption>出典 [7] JVN「JVN#82782759 Apache Struts 2 RESTプラグインにおける、@StrutsParameterの制限が@J…（jvn.jp・2026年10月29日 14:31 当サイト取得）</figcaption></figure>

**企業・担当者が確認すること：** Struts 2のRESTプラグインを使うシステムは、バージョンと `@JsonAnySetter` の使用有無を確認し、更新と設定の追加を行ってください。すぐに更新できない場合は、値を格納する前にアプリケーション側で検証するワークアラウンドが示されています [7]。

### 6. アララのメール配信サービスに不正アクセス、メールアドレス約301万件が持ち出し

ペイクラウドホールディングスは2026年10月29日、連結子会社のアララが運営するメール配信サービスのサーバーシステムに外部から不正アクセスがあり、個人情報の一部が外部へ流出したと公表しました。不正アクセスは10月28日に確認し、当該サーバーを直ちにネットワークから切り離したとしています [9]。
不正アクセスを受けたのは1システムで、この環境を利用する企業が保有するメールアドレス約301万件が外部に持ち出されたことを確認しています。原因はWebサーバーの脆弱性を第三者に悪用されたことで、現時点でほかの不正アクセスによる影響は確認されていないとしています [9]。

**企業・担当者が確認すること：** アララのメール配信サービスを利用している企業は、自社が保有するメールアドレスが対象に含まれるかを同社に確認し、顧客への注意喚起を検討してください。同社は、心当たりのない不審なメールのURLにアクセスせず削除するよう呼びかけています [9]。

### 7. モイ、「ツイキャス」のサーバーへの不正アクセスを公表しサービスを停止

モイは2026年10月28日、同社が運営するライブ配信サービス「ツイキャス」のサーバーに、第三者による不正アクセスが行われた形跡を確認したと公表しました（第一報）。同日10時30分頃にシステムの異常を検知し、外部からの不正アクセスの痕跡を確認したとしています [10]。
被害拡大を防ぐため、同日10時40分頃から「ツイキャス」とコーポレートサイト等を緊急メンテナンスとして停止しています。安全性を確認したうえで再開する予定で、復旧までには相応の時間がかかる見込みです。詳細や原因、再開時期は確認でき次第公表するとし、当面はTDnetと同社の公式Xアカウントで情報を出すとしています。業績への影響は精査中です [10]。

**企業・担当者が確認すること：** ツイキャスと連携している配信や外部サービスがある場合は、同社の続報で影響範囲と再開時期を確認してください。問い合わせ先はsupport@twitcasting.tvです [10]。
